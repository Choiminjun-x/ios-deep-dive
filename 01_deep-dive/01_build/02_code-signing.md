# iOS 코드 서명

> 작성일: 2026-10-07

## 큰 그림

```
① 컴파일 → ② 링킹 → ③ 패키징 → ④ 코드 서명    ← 여기까지 빌드
                                       ↓
                       ⑤ 실행 (기기가 서명 확인 + dyld)
```

**코드 서명** = 빌드의 마지막 단계에서 `.app`에 찍는 "**내가 만들었고, 아무도 손대지 않았다**"는 도장
- 내용을 숨기는 **암호화가 아님** → 바뀌었는지, 누가 만들었는지만 확인

## 1. 도장은 무엇으로 만들어지나

### ① 지문 (해시)

파일 내용을 넣으면 짧은 값 하나가 나오는 계산

```
"Hello"   → 185f8db3…
"Hello!"  → 334d016f…   ← 한 글자만 달라도 완전히 다른 값
```

- 지문을 비교하면 **파일이 바뀌었는지** 알 수 있음
- 하지만 지문만으로는 부족함 → 앱을 고친 뒤 지문도 새로 계산해서 바꿔치기할 수 있기 때문

### ② 열쇠 한 쌍 (비밀키 + 공개키)

| 열쇠 | 다른 이름 | 누가 가지고 있나 | 역할 |
|---|---|---|---|
| 비밀키 | 개인키, private key | **나만** (내 Mac 키체인) | 지문에 도장을 **찍음** |
| 공개키 | public key | **누구나** | 도장이 진짜인지 **확인함** |

- 서명은 **항상 비밀키로 찍음** → 나만 가진 열쇠여야 "내가 했다"가 증명됨
- 참고: 암호화는 방향이 반대 (공개키로 잠그고, 비밀키로 엶)

### ③ 도장 찍기와 확인

```
[내 Mac, 빌드]
앱 내용 → 지문 계산 (42) → 비밀키로 변환 → 도장 ("X7Q9")

[iPhone, 설치·실행]
A. 지금 앱 내용 → 지문 직접 계산              → 42
B. 도장 "X7Q9" → 공개키로 확인 → 원래 지문    → 42
→ A와 B가 같으면 ✅ 통과
```

| 상황 | A (지금 앱) | B (도장) | 결과 |
|---|---|---|---|
| 정상 | 42 | 42 | ✅ |
| 누가 앱 파일을 고침 | **57** | 42 | ❌ 앱이 바뀌었다 |
| 남이 자기 비밀키로 도장을 찍음 | 42 | **13** | ❌ 내가 찍은 게 아니다 |

### ④ 실제 앱에서는 "지문 목록"에 도장을 찍음

앱은 파일이 많아서, 파일·조각별 지문을 모은 **지문 목록**을 만들고 그 목록 전체에 도장을 찍음

```
지문 목록
 ├─ 실행 파일 조각들의 지문
 ├─ Info.plist 지문
 └─ 리소스 파일들의 지문
       ↑
  이 목록 전체에 비밀키로 도장
```

> **1단계 핵심:** **지문**은 "바뀌지 않았다"를, **비밀키 도장**은 "내가 찍었다"를 증명한다. 확인은 "지금 앱의 지문"과 "도장에 담긴 지문"이 같은지 비교하는 것이다.

## 2. 인증서, "이 공개키는 진짜 내 것"이라는 Apple의 보증서

### ① 왜 필요한가

앱 안에 도장과 공개키가 함께 들어가기 때문에, 나쁜 사람도 이렇게 할 수 있음

```
앱을 고침 → 자기 비밀키로 도장 → 자기 공개키를 넣음 → 짝이 맞으니 통과?
```

→ "**이 공개키가 정말 그 개발자 것인가?**"를 보증해 줄 누군가가 필요함 = **Apple**

### ② 인증서 안에 든 것

```
인증서 (Apple Development: 홍길동)
 ├─ 공개키          ← 1단계의 확인용 열쇠
 ├─ 누구 것인지      이름, Team ID (AB12CD34EF)
 └─ Apple의 도장    ← "위 공개키는 이 사람 것이 맞다"
```

- 비유: **신분증** (사진 = 공개키, 발급처 = Apple)
- ⚠️ **비밀키는 인증서 안에 없음** → 키체인에 따로 있고 인증서와 **짝**으로 묶여 있을 뿐
  - 비밀키가 인증서 안에 있었다면, 앱에 인증서를 넣는 순간 누구나 비밀키를 꺼낼 수 있음

### ③ 확인은 두 번

Apple의 공개키는 **모든 iPhone에 처음부터 내장**되어 있음

```
0. Apple 공개키(기기 내장) → 인증서의 Apple 도장 확인
   → "이 공개키는 홍길동 것이 맞다" ✅
B. 인증서 안의 내 공개키   → 앱의 도장 확인
   → "홍길동이 찍었고, 바뀌지 않았다" ✅
```

| 열쇠 | 확인하는 대상 |
|---|---|
| Apple 공개키 (기기 내장) | **인증서** |
| 내 공개키 (인증서 안) | **앱의 도장** |

→ 나쁜 사람이 자기 공개키를 넣어도 Apple 도장이 없어서 0번에서 걸림

### ④ 인증서가 만들어지는 과정

```
내 Mac                                Apple
1. 열쇠 한 쌍 생성
   비밀키 → 키체인에 보관 (밖으로 안 나감)
   CSR (공개키 + 내 정보)  ──보냄──▶  2. Apple 도장 찍기
3. .cer 받음            ◀──돌려줌──  .cer (공개키 + 내 정보 + Apple 도장)
```

| 파일 | 만드는 쪽 | 비유 |
|---|---|---|
| **CSR** | 내 Mac | 신분증 **발급 신청서** |
| **.cer** | Apple | 발급된 **신분증** |

- Xcode의 Automatic Signing이나 Settings → Accounts를 쓰면 이 과정을 Xcode가 대신 함

### ⑤ 인증서는 어디에 있나

| 위치 | 이유 |
|---|---|
| **내 Mac 키체인** | 빌드할 때 서명에 사용 (비밀키와 짝) |
| Apple 개발자 사이트 | 발급 원본 기록 |
| 앱 안 (실행 파일의 서명 부분) | 기기가 공개키를 꺼내 도장 확인 |
| 프로비저닝 프로필 안 | "이 인증서로 서명한 앱만 허락" (3단계) |

키체인 접근 → 로그인 → **내 인증서**에서 확인

```
▼ Apple Development: 홍길동 (AB12CD34EF)   ← 인증서 = 공개키 (앱 안에 들어감)
    🔑 홍길동                               ← 짝인 비밀키 (Mac에만 있음)
```

- 비밀키가 아래에 붙어 있어야 서명 가능
- 터미널: `security find-identity -v -p codesigning` → 비밀키까지 있는 인증서만 표시

### ⑥ 다른 Mac으로 옮길 때

| 파일 | 들어 있는 것 | 서명 가능? |
|---|---|---|
| `.cer` | 인증서(공개키)만 | ❌ |
| `.p12` | 인증서 + **비밀키** | ✅ |

> **2단계 핵심:** 인증서 = 내 공개키 + 내 정보 + **Apple의 도장**. iPhone은 내장된 **Apple 공개키로 인증서**를 믿고, 인증서 안의 **내 공개키로 앱 도장**을 확인한다. 도장은 **인증서와 짝인 비밀키**로 찍는다.

## 3. 프로비저닝 프로필, Apple이 발급한 "실행 허가증"

### ① 왜 필요한가

인증서는 "**누가 만들었나**"만 증명함. Apple은 그 외에도 정해 두고 싶은 것이 있음

- 이 개발자가 만든 **어떤 앱**인가?
- **어느 iPhone**에 설치해도 되나?
- 푸시, iCloud 같은 **권한**을 써도 되나?
- **언제까지** 허락하나?

→ 이 답을 적고 Apple이 도장 찍은 문서 = **프로비저닝 프로필**

### ② 프로필 안에 든 것

```
프로비저닝 프로필 (Apple이 도장 찍음)
 ├─ 어떤 앱?        App ID: AB12CD34EF.com.example.myapp
 ├─ 누가 서명?      허용된 인증서: Apple Development: 홍길동
 ├─ 어느 기기?      허용된 기기 UDID 목록
 ├─ 무슨 권한?      푸시, App Group, iCloud …
 └─ 언제까지?       만료일
```

- 비유: **회사 출입증** (신분증 = 인증서로 누구인지 확인, 출입증 = 프로필로 어느 건물·층·기간인지 확인)

| 용어 | 뜻 |
|---|---|
| **App ID** | Team ID + Bundle ID. "이 앱"을 가리키는 이름표 |
| **Capabilities** | 개발자 사이트 App ID에서 켜는 기능 (푸시, NFC 등) = Apple의 **허락** |
| **Entitlements** | 프로젝트의 `.entitlements` 파일 = 앱의 **요청** |

- 기능을 쓰려면 **허락과 요청이 둘 다 있어야 함**
- Xcode → Signing & Capabilities → **+ Capability**로 추가하면 둘 다 처리됨 (Automatic Signing 기준)
- 참고: APNs 인증서/키는 서버가 푸시를 보낼 때 쓰는 것으로, 코드 서명과는 별개

### ③ 기기가 확인하는 다섯 줄

```
✅ 앱에 서명한 인증서  → 프로필의 허용 인증서에 있나?
✅ 앱의 Bundle ID      → 프로필의 App ID와 같나?
✅ 이 기기             → 프로필의 기기 목록에 있나?
✅ 앱이 요청한 권한     → 프로필이 허용한 권한 안에 있나?
✅ 프로필              → 아직 만료 전인가?
```

- 하나라도 어긋나면 설치·실행 거부
- **서명 에러의 대부분이 이 다섯 줄 중 하나가 안 맞는 경우**

### ④ 프로필 종류

| 종류 | 용도 | 기기 목록 |
|---|---|---|
| **Development** | 내 기기에서 개발·디버깅 | 있음 |
| **Ad Hoc** | 등록된 기기에 테스트 배포 | 있음 |
| **App Store** | App Store, TestFlight 배포 | **없음** (누구나 설치) |

### ⑤ 프로필은 어디에 있나

| 위치 | 설명 |
|---|---|
| 앱 안 | `MyApp.app/embedded.mobileprovision` (빌드할 때 Xcode가 넣음) |
| 내 Mac | `~/Library/Developer/Xcode/UserData/Provisioning Profiles/` |
| Apple 개발자 사이트 | Certificates, Identifiers & Profiles → Profiles |

- Automatic Signing을 쓰면 Xcode가 만들고, 내려받고, 앱에 넣는 것까지 알아서 함

> **3단계 핵심:** 인증서 = **누가**, 프로필 = **어떤 앱을, 어느 기기에서, 무슨 권한으로, 언제까지**. 프로필에도 Apple 도장이 찍혀 있고, 기기는 프로필과 앱이 일치하는지 다섯 줄로 확인한다.

## 4. 빌드할 때 도장이 실제로 찍히는 과정

### ① 언제, 누가 찍나

- 빌드의 **맨 마지막**에 Xcode가 **`codesign`** 도구를 실행함 (링킹 때 `ld`를 부른 것처럼)
- Xcode 빌드 로그(Report navigator) 마지막 쪽에서 확인 가능

```
CodeSign /…/MyApp.app
    codesign --sign "Apple Development: 홍길동 (AB12CD34EF)"
             --entitlements MyApp.app.xcent
             MyApp.app
```

### ② codesign이 받는 재료

| 재료 | 어디서 가져오나 | 관련 단계 |
|---|---|---|
| 인증서 + 비밀키 | Mac 키체인 | 2단계 (누가) |
| 프로비저닝 프로필 | Xcode가 내려받아 둔 것 | 3단계 (허가증) |
| Entitlements | `.entitlements` + 프로필 → Xcode가 `.xcent` 파일로 합침 | 3단계 (요청 권한) |

### ③ codesign이 하는 일 (순서대로)

```
1. 프로필을 앱 안에 복사           → embedded.mobileprovision
2. 리소스 파일마다 지문 계산        → _CodeSignature/CodeResources에 저장
3. 지문 목록 만들기                → 실행 파일 조각들 + Info.plist + Entitlements + 2번 파일
4. 지문 목록에 비밀키로 도장
5. 도장 + 인증서를 실행 파일 안에 넣기
```

- Entitlements도 지문 목록에 들어감 → 나중에 권한을 몰래 추가하면 지문이 달라져서 걸림

### ④ 결과: 서명이 남는 세 곳

```
MyApp.app/
 ├─ MyApp                          ← 도장 + 인증서 (실행 파일 안)
 ├─ _CodeSignature/CodeResources   ← 리소스 파일별 지문
 ├─ embedded.mobileprovision       ← 허가증
 ├─ Info.plist
 └─ Assets.car …
```

### ⑤ 서명 순서: 안쪽부터

```
1. Frameworks/Foo.framework   ← 먼저 도장
2. PlugIns/Widget.appex       ← 그다음
3. MyApp.app                  ← 마지막 (안쪽 도장 결과까지 지문 목록에 포함)
```

- 앱의 지문 목록이 안쪽 프레임워크의 지문까지 포함하기 때문
- 순서가 바뀌면 앱 도장을 찍은 뒤 안쪽이 바뀌는 셈 → 앱 도장이 깨짐
- 💡 **Embed & Sign**의 "Sign"이 바로 1번 (프레임워크를 복사하고 내 인증서로 도장)

### ⑥ 실무에서 기억할 것

- **서명이 끝난 뒤에는 `.app` 안을 건드리면 안 됨** → 파일 하나만 바뀌어도 기기에서 실행 안 됨
- Build Phases의 Run Script가 서명 뒤에 `.app` 안 파일을 수정하면 이 문제가 생김

> **4단계 핵심:** 빌드 마지막에 `codesign`이 **프로필을 넣고 → 지문 목록을 만들고 → 비밀키로 도장을 찍고 → 도장과 인증서를 실행 파일에 넣는다.** 순서는 안쪽(프레임워크)부터 바깥(앱)으로.

## 5. iPhone이 설치·실행할 때 확인하는 것

### ① 확인하는 것 두 가지

| 확인 | 질문 | 무엇으로 |
|---|---|---|
| **도장** | 내가 찍었고, 바뀌지 않았나? | 인증서 안의 내 공개키 (1~2단계) |
| **허가증** | Apple이 이 앱을 이 기기에서 실행하도록 허락했나? | `embedded.mobileprovision` (3단계) |

### ② 도장 확인 (1~2단계 복습)

```
0. Apple 공개키(기기 내장) → 인증서의 Apple 도장 확인 → "이 공개키는 내 것이 맞다"
A. 지금 앱의 지문을 직접 계산
B. 인증서의 내 공개키로 도장 확인 → 도장 찍을 때의 지문
→ A와 B가 같으면 ✅
```

### ③ 허가증 확인

허가증도 도장 원리를 한 번 더 씀

```
1. Apple 공개키(기기 내장) → 허가증의 Apple 도장 확인 → "진짜 허가증이 맞다"
2. 허가증 내용과 앱 비교 (3단계의 다섯 줄)
   ✅ 인증서   ✅ Bundle ID   ✅ 기기   ✅ 권한(요청 ⊆ 허락)   ✅ 만료일
```

### ④ 언제 확인하나

| 시점 | 확인하는 것 |
|---|---|
| **설치할 때** | 도장 + 허가증 전체 |
| **앱을 켤 때** | 실행 파일 도장, 프레임워크마다 도장 |
| **실행 중** | 실행 파일 조각을 처음 읽을 때마다 지문 비교 → 다르면 즉시 종료 |

- 실행 중 검사는 4단계의 "실행 파일 **조각별** 지문"과 연결됨 (필요한 조각만 그때그때 읽기 때문)

### ⑤ 링킹 세션과 연결되는 부분

- 앱을 켤 때 **동적 프레임워크마다** 도장을 확인함 → 동적 프레임워크가 많을수록 Pre-main이 느려지는 이유 중 하나
- 프레임워크는 **앱과 같은 팀(Team ID)의** 도장이어야 로딩됨 → 그래서 **Embed & Sign** 필요

### ⑥ App Store 앱은 다름

App Store 앱은 심사 후 **Apple이 자기 도장으로 다시 찍어서** 배포함

| 설치 방법 | 내 인증서·허가증이 만료되면 |
|---|---|
| Xcode로 설치 (Development) | 앱이 **안 켜짐** → 다시 빌드해서 설치 |
| Ad Hoc 배포 | 앱이 **안 켜짐** |
| **App Store / TestFlight** | 영향 없음 (Apple 도장이라서) |

- 개발용으로 깔아 둔 앱이 갑자기 안 켜지면 대부분 허가증 만료가 원인

> **5단계 핵심:** iPhone은 **도장**(내가 찍었고 안 바뀌었나)과 **허가증**(Apple이 이 앱·기기·권한을 허락했나)을 모두 확인한다. 설치할 때 전부, 켤 때와 실행 중에도 도장을 계속 확인한다.

## 6. 자주 보는 서명 에러

### ① 서명 에러는 세 종류뿐

| 종류 | 무엇이 문제인가 | 관련 단계 |
|---|---|---|
| **A. 도장을 못 찍음** | 내 Mac에 비밀키가 없음 | 2단계 |
| **B. 허가증과 안 맞음** | 허가증 다섯 줄 중 하나가 어긋남 | 3·5단계 |
| **C. 도장이 깨짐** | 도장 찍은 뒤 앱이 바뀜 | 4단계 |

### ② A. 도장을 못 찍음

**에러:** `No signing certificate "iOS Development" found` / `… is missing its private key`

- **원인:** 키체인에 인증서가 없거나, 인증서는 있는데 **짝인 비밀키가 없음** (다른 Mac에서 만든 인증서를 `.cer`로만 가져온 경우)
- **확인:** 키체인 접근 → 내 인증서 → 아래에 🔑 비밀키가 붙어 있나?
- **해결:**
  1. Xcode → Settings → Accounts → Manage Certificates → **+로** 새로 만들기
  2. 또는 원래 Mac에서 `.p12`로 내보내서 가져오기

### ③ B. 허가증과 안 맞음

에러에 **`Provisioning profile … doesn't include …`가** 보이면 이 종류. 어떤 줄이 안 맞는지 메시지가 알려 줌

| 에러 메시지 | 안 맞는 줄 | 해결 |
|---|---|---|
| `doesn't include signing certificate "…"` | 인증서 | 허가증에 내 인증서 추가 후 다시 받기 |
| `doesn't match the bundle identifier` | App ID | Bundle ID와 허가증의 App ID 맞추기 |
| `doesn't include the currently selected device` | 기기 | 기기 등록 후 허가증 다시 받기 |
| `doesn't support the … capability` / `doesn't include the … entitlement` | 권한 | App ID에서 Capability 켜고 허가증 다시 받기 |
| `Provisioning profile has expired` | 만료 | 허가증 다시 받기 |

- 공통 해결: **허가증 다시 받기** → 기기나 기능을 추가해도 이미 받은 허가증에는 반영되지 않기 때문
- Automatic Signing을 쓰면 Xcode가 대부분 자동으로 처리

### ④ C. 도장이 깨짐

**에러:** 실행하자마자 크래시, 로그에 `Code Signature Invalid` 또는 `CODESIGNING`

- **원인:** 도장 찍은 뒤 앱 안의 무언가가 바뀌었거나, 안쪽 프레임워크에 도장이 없음
- **해결 (우선순위 순):**
  1. Run Script가 **서명 뒤에** `.app` 안 파일을 수정하는지 확인 → 서명 전으로 옮기기
  2. 동적 프레임워크가 **Embed Without Signing**이면 → **Embed & Sign**으로 변경
  3. 다른 팀이 서명한 프레임워크 → Embed & Sign으로 내 인증서로 다시 서명

### ⑤ 에러가 아닌 것

**기기에서 "신뢰하지 않는 개발자" 팝업**
- 에러가 아니라 사용자 확인 단계
- 설정 → 일반 → **VPN 및 기기 관리** → 해당 개발자 신뢰

### ⑥ 한 장 요약

```
서명 에러 발생
 ├─ "certificate" / "private key" 언급     → A. 비밀키 문제 → 키체인 확인
 ├─ "Provisioning profile doesn't …"      → B. 허가증 불일치 → 무엇이 안 맞는지 읽고 허가증 다시 받기
 └─ 실행 크래시 "Code Signature Invalid"    → C. 서명 뒤 변경 → Run Script, Embed & Sign 확인
```

> **6단계 핵심:** 서명 에러는 **비밀키 없음 / 허가증 불일치 / 서명 뒤 변경** 중 하나다. 에러 메시지에서 어느 쪽인지 먼저 구분하면 원인을 바로 찾을 수 있다.

## 핵심 정리

1. **지문 + 비밀키 도장**으로 "내가 찍었고 안 바뀌었다"를 증명한다.
2. **인증서**는 내 공개키에 Apple이 도장을 찍은 신분증이다.
3. **프로필**은 어떤 앱을, 어느 기기에서, 무슨 권한으로, 언제까지 허락했는지 적은 Apple의 허가증이다.
4. 빌드 마지막에 **`codesign`이** 허가증을 넣고 지문 목록에 도장을 찍는다 (안쪽부터).
5. **iPhone**은 설치·실행 때 도장과 허가증을 모두 확인한다.
6. 에러는 **비밀키 없음 / 허가증 불일치 / 서명 뒤 변경** 중 하나다.
